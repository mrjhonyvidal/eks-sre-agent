# MCP gateway (App Runner)

This folder scaffolds an HTTP MCP gateway for the EKS AI Ops bot. It packages the
official AWS Labs `awslabs.eks-mcp-server` (stdio) behind a small FastAPI shim,
deploys it to **AWS App Runner** with a least-privilege IAM role, and wires the
two SSM parameters the bot already reads:

- `/eks-ai-ops-toolkit/mcp-gateway-url`
- `/eks-ai-ops-toolkit/mcp-gateway-api-key`

> **No bot code changes are required.** `eks_ai_ops.interactive.mcp_tools.MCPToolClient`
> already POSTs `{"server","tool","arguments"}` to `${MCP_GATEWAY_URL}/tools/call`
> with `Authorization: Bearer ${MCP_GATEWAY_API_KEY}`. The shim in `app/server.py`
> implements exactly that contract.

## Hosting options & cost (us-east-1)

| Option | ~Monthly | Setup effort | Notes |
|---|---|---|---|
| **App Runner** (this folder) | **~$5–7** | Low | 0.25 vCPU / 0.5 GB. Auto HTTPS, scale-to-1, IAM-native. **Recommended.** |
| ECS Fargate + ALB | ~$20+ | Medium | Overkill unless you already run ECS. |
| EC2 `t4g.nano` + systemd | ~$3 | Medium | Cheapest; you patch and watch it. |
| Local + ngrok | $0 | Trivial | Demo-only, ephemeral URL, no IAM. |

App Runner pricing reference: <https://aws.amazon.com/apprunner/pricing/>.
Cost above assumes idle most of the time with `MinSize=1` instance.

## What gets created

- ECR repo `eks-ai-ops-mcp-gateway`
- IAM role `eks-ai-ops-mcp-instance` (App Runner *instance role*) with:
  - `eks:DescribeCluster`, `eks:ListClusters`, `eks:AccessKubernetesApi`
  - CloudWatch Logs read
- IAM role `eks-ai-ops-mcp-ecr-access` (App Runner *access role* for ECR pulls)
- EKS **access entry** binding the instance role to `AmazonEKSViewPolicy`
  on cluster `eks-ai-ops` (read-only — no mutations).
- App Runner service `eks-ai-ops-mcp-gateway`
- SSM `String` params for URL + bearer key

## Files

```text
infrastructure/mcp-gateway/
  Dockerfile                     # python:3.12-slim + kubectl + the shim
  apprunner.yaml                 # informational; deploys via ECR
  app/
    server.py                    # FastAPI shim (POST /tools/call → MCP stdio)
    requirements.txt
  iam/
    instance-trust-policy.json   # tasks.apprunner.amazonaws.com
    instance-policy.json         # least-privilege EKS read
    access-trust-policy.json     # build.apprunner.amazonaws.com (ECR pulls)
  scripts/
    setup.sh                     # build → push → IAM → access entry → service → SSM
    teardown.sh                  # reverses all of the above
```

## Deploy

```bash
chmod +x infrastructure/mcp-gateway/scripts/*.sh

# Dry-run first — prints every command without touching AWS
./infrastructure/mcp-gateway/scripts/setup.sh

# Real deployment
DEPLOY=1 ./infrastructure/mcp-gateway/scripts/setup.sh
```

`setup.sh` is idempotent — re-running updates the image and the SSM URL/key.
After it finishes, redeploy the main stack so the bot Lambda picks up the new
env vars:

```bash
make deploy
```

Then in Slack (inside an incident thread or at channel level):

```text
@EKS AI Ops list pods in kube-system
@EKS AI Ops describe deployment coredns in kube-system
@EKS AI Ops show recent logs for pod <name> in kube-system
```

## Tear down

This folder's resources are **not** part of `make destroy` by default — they're
deployed by a separate script. Two options:

```bash
# Option A — run the dedicated script
./infrastructure/mcp-gateway/scripts/teardown.sh

# Option B — run the project-wide chained teardown
make destroy-mcp        # only this gateway
make destroy-confirm    # everything (now also calls destroy-mcp)
```

## Configuration knobs

All of these are optional environment variables read by `setup.sh` /
`teardown.sh`:

| Var | Default | Meaning |
|---|---|---|
| `AWS_REGION` | `us-east-1` | Region |
| `CLUSTER_NAME` | `eks-ai-ops` | EKS cluster the gateway should query |
| `MCP_SERVICE_NAME` | `eks-ai-ops-mcp-gateway` | App Runner service name |
| `MCP_ECR_REPO` | `eks-ai-ops-mcp-gateway` | ECR repo |
| `MCP_INSTANCE_ROLE` | `eks-ai-ops-mcp-instance` | Task role |
| `MCP_ACCESS_ROLE` | `eks-ai-ops-mcp-ecr-access` | ECR pull role |
| `MCP_API_KEY` | random hex | Bearer token; written to SSM |

## Security notes

- The bearer token is generated by `openssl rand -hex 24` and stored as an
  SSM `String` (the SAM template can't dereference `SecureString`).
  Rotate by re-running `setup.sh` and `make deploy`.
- The instance role uses `AmazonEKSViewPolicy` (read-only). Tools that mutate
  the cluster will fail with 403 — by design.
- App Runner serves on a public HTTPS URL. Anyone with the bearer token can
  call `/tools/call`. Treat the SSM key parameter accordingly.

## Local-only alternative (free, demo-grade)

If you only want to verify the wiring once:

```bash
# In one terminal
pip install -r infrastructure/mcp-gateway/app/requirements.txt
MCP_GATEWAY_API_KEY=demo \
  uvicorn server:app --app-dir infrastructure/mcp-gateway/app --port 8080

# In another
ngrok http 8080
# Then:
aws ssm put-parameter --name /eks-ai-ops-toolkit/mcp-gateway-url --type String \
  --overwrite --value "https://<ngrok-id>.ngrok.app/"
aws ssm put-parameter --name /eks-ai-ops-toolkit/mcp-gateway-api-key --type String \
  --overwrite --value "demo"
make deploy
```

Stop ngrok + your shell when done — nothing to clean up in AWS beyond the two
SSM params (`make destroy-mcp` removes them).
